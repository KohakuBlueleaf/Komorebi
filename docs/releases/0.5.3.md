# Komorebi 0.5.3

A patch release of [0.5.2](0.5.2.md) with two fixes to what a handler's compute case
begins with: the packer's formats are named at compile time, so the pack CPU keeps no
table of them in its stack's room, and the Dst clear builds for Wormhole. Nothing a
0.5.2 script uses is removed or changed.

## The packages

| Distribution | Version | Imported as | What it carries |
|---|---|---|---|
| `komorebi-tt` | 0.5.3 | `komorebi` | as in 0.5.0, 0.5.1 and 0.5.2 |
| `komorebi-runtime` | 0.81.1.4 | `komorebi_runtime` | unchanged since 0.2.0: tt-metal v0.81.1 with our patches, built with its X280 runtime, for a Blackhole P150A |

`pip install -U "komorebi-tt[runtime]"` takes 0.5.3; the runtime is not built again
and the `runtime` extra still asks for `komorebi-runtime` 0.81.1.4 or later, below
0.81.2 ([install](../install.md#from-010-the-two-wheels)).

## Fixed since 0.5.2

- **The packer's formats at a handler's entry are named at compile time.** In a
  program with a `km.kernel` handler not made `clean=True` and a DSL handler, each DSL
  handler's compute case begins with the start-up's formats set again, and the runtime
  form's commands do the same at their start. The packer's line was the library's
  `pack_reconfig_data_format(index)`, which reads the build's per-buffer tables; in a
  large pack kernel the compiler kept one call out of line, and the tables then lay in
  the pack CPU's local memory, which on Blackhole is the stack's room: 128 B in a
  program of fourteen handlers, whose pack CPU was left 16 B of stack. The line is now
  `km::pack_format<index>()` (`device/core/km_pack_format.hpp`): the same statements
  with the index a template argument, always inline, so the pack CPU holds no copy of
  the tables however many handlers set them. That program's pack kernel holds 312 B of
  data where it held 440, and its pack CPU has 144 B of stack to spare
  ([A handler that is a hand-written kernel](../reference/classes.md#a-handler-that-is-a-hand-written-kernel)).
- **The Dst clear at a handler's entry builds for Wormhole.** Beside a hand kernel not
  made clean, a DSL handler's compute case begins with Dst cleared whole. The clear was
  written in Blackhole's form of `ZEROACC`, five operands; Wormhole's takes three, so
  such a program did not compile for Wormhole. The line is now written in each chip's
  form; Blackhole's is the one it was
  ([A handler that is a hand-written kernel](../reference/classes.md#a-handler-that-is-a-hand-written-kernel)).

## Upgrading from 0.5.2

Nothing a 0.5.2 script imports from `komorebi` was removed, added or changed. A program
whose DSL handlers set the start-up's formats again, or a runtime form's compute, now
includes `km_pack_format.hpp` and calls `km::pack_format<index>()` where it called
`pack_reconfig_data_format(index)`, the same statements: its generated text and build
folder change. A class with a `km.kernel` handler not made clean beside a DSL
handler, which did not compile for Wormhole, now builds there. As before, build your
kernels against the headers of the version you run.
