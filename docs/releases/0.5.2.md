# Komorebi 0.5.2

A patch release of [0.5.1](0.5.1.md) with three fixes: the make no longer refuses a
class whose buffers the load takes, a load that fails before anything was launched
gives back the L1 it took, and two fields whose header names meet are refused at the
make, where the kernels failed. Nothing a 0.5.1 script uses is removed or changed.

## The packages

| Distribution | Version | Imported as | What it carries |
|---|---|---|---|
| `komorebi-tt` | 0.5.2 | `komorebi` | as in 0.5.0 and 0.5.1 |
| `komorebi-runtime` | 0.81.1.4 | `komorebi_runtime` | unchanged since 0.2.0: tt-metal v0.81.1 with our patches, built with its X280 runtime, for a Blackhole P150A |

`pip install -U "komorebi-tt[runtime]"` takes 0.5.2; the runtime is not built again
and the `runtime` extra still asks for `komorebi-runtime` 0.81.1.4 or later, below
0.81.2 ([install](../install.md#from-010-the-two-wheels)).

## Fixed since 0.5.1

- **The make no longer refuses buffers the load would take.** The room a class's
  buffers are made against counted the host transfer buffer's row for a program with
  no buffers and no overlays, where the chunk is the largest page's (a row of 82,000 B
  or more). The load counts the row for the real program and takes the 16 KiB chunk
  (32,848 B) whenever the larger one would not leave room, so the make refused classes
  the load accepts, by 49,152 B on every session. The make now counts the row at its
  least, the 16 KiB chunk's, by the one function the load uses; the load still refuses
  by its own table what does not fit. A class whose sizes are all given builds to the
  same text; a symbol solved against the L1 the buffers leave gets the larger room
  ([Making and calling](../reference/classes.md#making-and-calling)). The reference's
  example of a merge that does not fit changed with it: the gate class's `BLOCK = 9`
  merged with Linear asks 1,683,456 B as one set and 1,384,448 B at shared indices, of
  the 1,372,096 B left; `BLOCK = 8` fits only at shared indices (1,363,968 B)
  ([Classes merged into one](../reference/classes.md#classes-merged-into-one)).
- **A load that fails gives back the L1 it took.** A load that failed before anything
  was launched (its kernels larger than the kernel buffer, for one) left the backend's
  L1 tensors allocated: the host transfer buffer, the control blocks and the page
  bounds list. A build made while that error was being handled, as a merge's rebuild
  with a handler moved to an overlay is, saw that much less room, reported as "L1 held
  by the session": 50,048 B on one card, and on each island of a split card. The
  failing load releases what it took, on one card and over islands
  ([merged_class](../../experiments/language/merged_class/README.md)).
- **Two fields whose header names meet are refused at the make.** A field gives the
  program's header `kField<Name>`, `kField<Name>Pages` and, for a field of raw pages,
  `kField<Name>PageBytes`. Two fields such as `out` and `out_pages`, in one class or
  one in each class of a merge, were accepted and the kernels then failed with a name
  defined twice. The make refuses them, naming both fields and the name they share
  ("rename one"; [Fields](../reference/classes.md#fields)).

## Upgrading from 0.5.1

Nothing a 0.5.1 script imports from `komorebi` was removed, added or changed. A class
whose sizes are all given and that fits builds to the same text. A class that leaves
one symbol of its plan to be solved against the L1 its buffers leave, made with a
session, is solved against 49,152 B more: its symbol can come out larger and its build
folder changes with it; give the symbol in the plan to keep a size. A class whose buffers the load takes is no longer
refused for the row of a program of none: "its buffers take ... B, ... B left" now
refuses only past the room the 16 KiB chunk's row leaves, and the gate class's
`BLOCK = 8` merged with Linear, refused before, fits only at shared indices (its load
then needs a kernel buffer larger than the default, as
[merged_class](../../experiments/language/merged_class/README.md) says). Two fields that
give the header one name, which did not compile, are now refused at the make: rename
one. As before, build your kernels against the headers of the version you run.
