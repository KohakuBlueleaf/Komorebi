# Komorebi 0.5.1

A patch release of [0.5.0](0.5.0.md). It fixes messages across islands, which did not
compile in 0.5.0, and adds to classes: handlers share their stream and table buffers
when a class's do not fit, an own field may be raw pages and take an index past 25, a
body may fill two write streams in one loop, and a body's relative include keeps its
meaning in a merge. Nothing a 0.5.0 script uses is removed or changed.

## The packages

| Distribution | Version | Imported as | What it carries |
|---|---|---|---|
| `komorebi-tt` | 0.5.1 | `komorebi` | as in 0.5.0: the framework and the `kmr` command, the class and tile compilers, the device and ABI headers, the sources of both dispatchers and the X280 dispatcher's image, the native host module |
| `komorebi-runtime` | 0.81.1.4 | `komorebi_runtime` | unchanged since 0.2.0: tt-metal v0.81.1 with our patches, built with its X280 runtime, for a Blackhole P150A |

`pip install -U "komorebi-tt[runtime]"` takes 0.5.1; the runtime is not built again
and the `runtime` extra still asks for `komorebi-runtime` 0.81.1.4 or later, below
0.81.2 ([install](../install.md#from-010-the-two-wheels)).

## Fixed since 0.5.0

- **Messages across islands.** In 0.5.0 a program with dynamic messages on two or more
  islands did not compile: the far write gained a form (confirmed or posted) with no
  default, and the three calls by which a message reaches another island's rank did
  not name it. They give the confirmed form, which is what they were
  ([dynamic handlers](../reference/dynamic.md)).
  `komorebi.tools.card_check` also sets the tree's runtime root before its shared open,
  as `km.Session` does.
- **A merge's refusal of one field name declared differently** now says what differs:
  the format and shape, `push=` or raw pages against tiles, where it printed the field
  twice alike when only `push=` or `raw=` differed
  ([Classes merged into one](../reference/classes.md#classes-merged-into-one)).

## New since 0.5.0

- **Handlers share their stream and table buffers when a class's do not fit.** A
  handler's streams, tables of entries and out buffers live for one call, so the build
  shares them among the handlers when the class's buffers do not fit indices 0 to 25 as
  one set, taking three ways in turn: as one set for the program (a class that fits
  builds to the same text as before); shared by shape (a stream takes a pair another
  handler has of the same role, format and page bytes; nothing runs for it on the
  card); at shared indices of other pages (each index as large as its largest use, a
  handler's pages set at its entry). There is no option for it; the build report
  (`program.txt`) gives the way taken and what is shared, and the make names what each
  way said when none fits. A class with a chain takes the first two ways only, and its
  refusal names the handlers and the streams whose page bytes differ. At the third way
  commands of handlers that give an index other pages do not overlap on a core: in
  [34_shared_buffers](../../examples/34_shared_buffers/README.md) such a change costs
  5.88 µs a command on 12 cores and 6.14 µs on 120 (Blackhole p150a, 2026-11-25, the
  median of five runs). Merges, islands, X280 threads and `km.kernel` handlers work
  with all three ways
  ([When a class's buffers do not fit](../reference/classes.md#when-a-classs-buffers-do-not-fit),
  [hazards](../reference/hazards.md#two-handlers-that-give-an-index-other-pages-on-one-core)).
- **An own field of raw pages, and own fields past index 25.**
  `km.own(push=..., raw=True)` makes an own field a plain buffer of raw pages, not
  tiles: its first size is its pages, the others a page's items; the header gives
  `kField<Name>`, `kField<Name>Pages` and `kField<Name>PageBytes`. An own field that
  finds no index from 8 to 25 takes one from 32 up (never 33), to the chip's last.
  Example 33 gains a second hand handler, `note`, on a raw field
  ([A body's own buffer](../reference/classes.md#a-bodys-own-buffer),
  [33_kernel_handler](../../examples/33_kernel_handler/README.md)). A class accepts
  `compute={"enable_trisc2_rvv": "if_present"}` as a hand program does.
- **A body may fill two write streams in one loop.** The second stream a body fills
  gets names of its own, where before the two were declared with one pair of names and
  did not compile; example 34's pack body writes two outputs this way
  ([A write stream bodies fill](../reference/classes.md#a-write-stream-bodies-fill)).
- **A body's relative include keeps its meaning in a merge.** A relative path of
  `include=` or of a body's `#include` lines is relative to the class's own build
  folder; a merge writes it as the path from the merged program's build folder, where
  before it named no file ([Inline bodies](../reference/classes.md#inline-bodies)).
- **A class constant that meets a handler's name in the thread header** is refused at
  the make ("rename the constant"), where the thread's C failed with "redefined".

## Upgrading from 0.5.0

Nothing a 0.5.0 script imports from `komorebi` was removed or added; `km.own` takes
`raw=` (False by default). A class whose buffers fit as one set builds to the same text
and loads the same kernels, a class that built before with a body filling one write
stream builds to the same text, and a class built alone keeps its includes as written.
A class whose buffers do not fit as one set is now built by the second or third way, by
itself. A switching run and a class added to a live run refuse a program at the
third way, or with a buffer at index 32 or above, naming it. An own field at 32 or above
is not rewound after a give-up: a body that leaves pages in one clears it itself. As
before, build your kernels against the headers of the version you run.

## Experimental

As in 0.5.0 ([Experimental](0.5.0.md#experimental)): Wormhole, kernels written as
classes and tile functions, three islands or more, and the Komorebi IR.

## Known not to work

As in 0.5.0 ([Known not to work](0.5.0.md#known-not-to-work)); the hazards page adds
the rule of the third way above, that commands of handlers that give an index other
pages do not overlap on a core.
